Authentication Detection Benchmark

Measure what changes when a detection rule is tuned.

Synthetic lab result

40 → 20 false alerts

Problem and audience

A rule that catches more suspicious sequences can also generate more work for an analyst. This benchmark compares 12 settings on 240 tuning cases, then reports results on 240 separately seeded holdout cases.

Implementation

The runner varies the failure count and time window, chooses a setting by F1 with precision as a tiebreaker, and compares it with the default on holdout data.

Python · precision · recall

Validation and results

Precision improved from 51.8% to 78.3% and recall from 35.8% to 60.0%. False alerts fell from 40 to 20 on the synthetic holdout.

Limitations and lessons

Both rules miss all 40 distributed-source cases. The splits share scenario templates, so these results do not establish production performance.

What changed on the holdout split

Default rule: 3 failures in 10 minutes · 43 true positives, 40 false positives, 77 missed cases.

Tuned rule: 4 failures in 20 minutes · 72 true positives, 20 false positives, 48 missed cases.

The wider window recovered slower patterns. The higher threshold also missed eight rapid cases. A team tuning this rule would need to decide which missed cases carry the greatest risk and test conditions that resemble its own log traffic.
